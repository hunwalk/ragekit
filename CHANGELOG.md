# Changelog

All notable changes to RageKit. Versions follow [semantic versioning](https://semver.org); while
RageKit is on 0.x, a minor version (0.1 → 0.2) may break things, and the entry says what and how
to update. Patch versions (0.1.0 → 0.1.1) only fix things.

"Breaking" covers more than the PHP API: the `.rk` template syntax, the core element contract
(what every kit accepts), the `kit.yml` and `module.yml` formats, the C functions a module library
implements, and `project.yml` options. Kits and modules distributed as Composer packages should
require the RageKit minor version they were written for, e.g. `"ragekit/ragekit": "^0.3"`.

## [Unreleased]

### Added

- **Focus from PHP:** `ref="search"` on an Entry or Textarea, and `$this->focus('search')` in a
  screen (or `onPress="focus('search')"` in a template) gives it the keyboard focus. Kits: an element
  declares `focus: <int property>` in kit.yml (see docs/kits.md).
- **Clipboard:** `RageKit\Clipboard::copy($text)` and `Clipboard::paste()`, text only, through an
  open window (normal and Nano builds, `ragekit dev`). See docs/state.md, "Clipboard". Backends gain
  `copyText()`/`pasteText()`; the bridge exports `rk_clipboard_set`/`rk_clipboard_get`.

- **`<ScrollView virtual="true">`** for long lists: only the rows in view exist (Slint's ListView,
  generated by RageKit, no widget style needed). 5000 chat bubbles: about 36 MB instead of 128 MB.
  stickToBottom, onTop and older rows added above keep working (the view keeps its place by itself).
  See docs/templates.md, "Long lists".
- **Collections update in place at the front too**: rows added at the front of a collection (older
  messages) are inserted there, and rows dropped from the front are removed there, instead of every
  row being rewritten (bridge and `ragekit dev`).
- **Tray and notifications on Windows:** the tray module uses the taskbar's notification area (left
  click = `onClick`, right click = the menu; png, ico or svg icons) and the notifications module
  shows toast notifications (clicks and `close()` work; the app registers itself under
  `HKCU\Software\Classes\AppUserModelId`, no installer needed). See docs/modules.md.
- **Audio plays Opus in MP4** (voice notes recorded in browsers): libopus on Linux (loaded at runtime),
  Media Foundation on Windows (also AAC/M4A); `Sound::load()` errors say why a file can't be played
  (new module function `audio_load_error`).
- **Notifications: replies and a badge.** `Notification::show(…, onReply: fn(string $text) => …)` adds a
  reply field (Windows toasts, KDE's inline reply); `Notification::badge($count)` puts a number on
  the taskbar button (Windows) or dock icon (Unity launcher API: KDE, Ubuntu's dock). The module's
  `notifications_show` takes a `reply` placeholder and posts "replied"; new `notifications_badge`.
- **`<ImageViewer source="…">`:** an image that zooms with the wheel (around the pointer), pans by
  dragging and switches between fitted and 100 % on a double-click. See docs/templates.md.
- **`<Shortcut capture="true" enabled="{{ … }}">`:** keys the window sees before a focused input
  (Tab, arrows, Return), only while the condition holds, e.g. Tab taking a suggestion.
  `RageKit\Emoji::suggest('tad')` lists matching `:shortcodes:`.
- **`<Dialog onDismiss="method">`:** runs after Esc or a click outside closed the dialog.
- **Scroll to a row:** `<ScrollView ref="thread">` and `$this->scrollTo('thread', $row)` in a screen
  put that row in the middle of the view (plain and virtual lists); `scrollToEnd('thread')` goes to
  the end and sticks there again. `keys="true"`: Page Up / Page Down scroll it, even from an input. See docs/templates.md, "ScrollView".
- **Formatted text:** `<Text markdown="true" onLink="method">` draws chat-style markdown: bold,
  italic, code, links (also bare URLs; a click runs onLink with the URL), bullet lists, fenced code
  blocks, line breaks and `:shortcodes:`, parsed natively through Slint's StyledText. Kits: Text
  declares `markdown`, a `styled` property and `onLink` (docs/kits.md); both kits do.
- **Colour emoji:** `<Emoji text="…" size="32" />` draws emoji as colour images from the system's
  emoji font (Noto Color Emoji through HarfBuzz on Linux, Segoe UI Emoji through DirectWrite on
  Windows), which the software renderer can't draw in text; `RageKit\Emoji::only()` / `count()` find
  emoji-only messages. See docs/templates.md, "Emoji". app.slint gains the `RkRich` and `RkEmoji`
  globals, answered natively for every window.
- **Pasting images:** `Clipboard::image()` saves the clipboard's image (a screenshot, an image copied
  in a browser, or a copied image file) in the app's cache folder and returns its path;
  `Clipboard::hasImage()`. `<PasteImage onPaste="method" />` runs a handler on Ctrl+V when the
  clipboard holds an image, even in a focused input (text still pastes as usual). Linux: X11/XWayland,
  or wl-paste; Windows: PNG, bitmaps (saved as png) and copied files. See docs/state.md and
  docs/templates.md. Backends gain `pasteImage()`/`clipboardHasImage()`; the bridge exports
  `rk_clipboard_image`/`rk_clipboard_has_image`; window components declare `rk-has-image()`.
- **dialogs module: the OS's file dialogs.** `RageKit\Dialogs\FileDialog::open()` / `save()` /
  `folder()` with a title, file type filters, several files and a start folder; the paths come back
  in a callback, the app keeps running meanwhile. Linux: xdg-desktop-portal (GNOME, KDE, Flatpak);
  Windows: the common item dialogs. See docs/modules.md, "The dialogs module".

### Fixed

- **No more "Recursion detected" for a View in a View:** a plain column `<View>` inside another
  `<View>` (a quote inside a chat bubble) with wrapping text made Slint's layout recurse at run time;
  such a View is now laid out as a column without a flexbox, like the ones in a `@foreach` (same look).
- **`focus()` puts the caret at the end** of the input's text (Entry and Textarea in both kits): text PHP set in the same handler (a picked suggestion) is typed after, not into.

- **slint-compiler no longer crashes on a list of cards**: a column `<View>` repeated by `@foreach`
  inside another `<View>`, with wrapping text, made it overflow its stack. Such a View is now laid
  out as a plain column (same look).
- **Readable layout errors**: when slint-compiler finds a binding loop (sizes depending on each
  other) or crashes, the build shows a few of its errors and a hint instead of dozens. See
  docs/templates.md, "Layout limits".

## [0.7.0] - 2026-10-26

What a real desktop app needs around its UI, driven by a dev-null.sh client.
Signed API requests with a key kept in the OS keyring, a browser sign-in that comes back through an
app link, a chat view that scrolls like a messaging app, desktop notifications and a tray icon.
Tested on Linux (Xvfb, and by hand on GNOME 48) and Windows (notifications and the tray are Linux
only for now); macOS isn't supported.
Nothing changes for 0.6 apps. Custom backends and kits: see "Changed".

### Added

App:

- **Timers.** `RageKit\Timer::every(5, fn() => …)` runs a function every 5 seconds until
  `stop()`, `Timer::after(0.5, fn() => …)` once. Ticks run on the UI thread like clicks: the
  windows show the new values afterwards, and an uncaught exception goes to
  `App::uncaughtException()`. Normal and Nano builds and `ragekit dev`. See docs/state.md,
  "Timers: polling and delays".
- **App links** (`ragekit: { links: [myapp] }`): the app runs as a single instance; another launch,
  by a `myapp://…` link or plainly, hands over to it, which comes to the front and gets
  `App::linkOpened($url)`. `Links::register('myapp')` makes the app the OS's handler (Linux: a
  .desktop file and mimeapps.list; Windows: the registry). `Links::openInBrowser($url)` and
  `Links::query($url)` (Nano builds have no `parse_str()`). Built apps only, not `ragekit dev`.
  On Linux such an app runs on XWayland when it can: GNOME's Wayland lets a window come forward
  only with an activation token, which browsers don't hand over yet (the token is used when one
  comes; `RAGEKIT_WAYLAND=1` keeps Wayland).
  See docs/links.md.
- **Windows:** `Window::hide()` / `show()` (a window off the screen keeps its screens' state) and
  `Window::raise()`.
- **App icon** (`ragekit: { icon: assets/icon.png }`): every window shows it, it's copied next to
  the executable and named in the `.desktop` file of `Links::register()`; on Windows a png also
  becomes the `.exe`'s icon (an `.ico` wrapping the png).
- **`App::cacheDir()`:** a folder for the app's cache files (`~/.cache/<app>` on Linux,
  `%LOCALAPPDATA%\<app>` on Windows), created on first use.
- **`RageKit\LocalTime`:** `format('H:i', $timestamp)` and `offset()` in the computer's own
  timezone (an app's `date()` is UTC). See docs/state.md, "Local time".

- **`ragekit package`** makes a `.tar.gz` (a folder that runs from anywhere) or a `.deb` (installs
  into `/opt` with a menu entry, the icon, the app's link schemes, and `Depends:` computed by
  `dpkg-shlibdeps`) in `dist/`. Metadata: `ragekit: { package: { version, description, … } }`. See
  docs/getting-started.md, "Packaging".

Templates:

- **`<ScrollView>`**: a column that scrolls (wheel, drag, its own scrollbar). For chats:
  `stickToBottom` (opens and stays at the bottom while the user is there), `anchor="bottom"` (rows
  added above don't move what's shown) and `onTop` (a handler to load older rows). Built by the
  compiler, so it works the same with every kit. See docs/templates.md, "ScrollView".
- **`<Entry onSubmit="send">`**: a handler for Return. The value is up to date when it runs.
- **Pressable Views, context menus and shortcuts.** `<View onPress onHoverIn onHoverOut>` (React
  Native's Pressable names); `<ContextMenu>` with `<MenuItem>`s inside a View opens at the pointer
  on a right-click; `<Shortcut keys="Ctrl+F" onPress="find" />` handles a key combination while its
  screen shows (also while typing in an input, for keys the input doesn't use). See
  docs/templates.md, "View", "ContextMenu" and "Keyboard shortcuts".
- **A chat composer:** `<Textarea rows="1" maxRows="8" onSubmit="send">` grows with its text up to
  `maxRows` lines, then scrolls (keeping the caret in view); with `onSubmit`, Return sends and
  Shift+Return or Alt+Return adds a line.

Modules:

- **Crypto** (`modules: [crypto]`): `Ed25519Key` (generate, sign, verify), `Ssh` (the
  `ssh-ed25519` public key line, its `SHA256:` fingerprint, and SSHSIG signatures as
  `ssh-keygen -Y sign` makes them), `Hash::sha256/sha512` and `Random::bytes`. Monocypher 4.0.2
  underneath. See docs/modules.md, "The crypto module".
- **Keyring** (`modules: [keyring]`): `Keyring::set/get/delete` keep secrets in the OS's credential
  store: the Secret Service (GNOME Keyring, KWallet) through libsecret on Linux, loaded at runtime;
  Credential Manager on Windows. A locked keyring is an error, never "nothing stored". See
  docs/modules.md, "The keyring module".
- **Notifications** (`modules: [notifications]`): `Notification::show($title, $body, onClick:,
  onClose:)` on Linux desktops (the freedesktop notification service through GLib, loaded at
  runtime). See docs/modules.md, "The notifications module".
- **Tray** (`modules: [tray]`): `Tray::show($icon, $tooltip, onClick:)` with a menu (`item()`,
  `separator()`), on Linux desktops with a StatusNotifierItem host (KDE, XFCE, GNOME with the
  AppIndicator extension). With `Window::hide()` an app keeps running in the tray when its window
  is closed. See docs/modules.md, "The tray module".
- **Uploads in the http module:** `RageKit\Http\Multipart` builds a `multipart/form-data` body
  (fields and files, any bytes), sent with `Request::multipart()`.
- **Recording in the audio module:** `Recorder::start(onLevel:, onFull:)` / `stop($path)` records a
  voice note (16 kHz mono WAV, up to 61 s) and returns a `Recording` with its length and a 48-bar
  waveform; `Sound::speed()` plays faster or slower. See docs/modules.md, "Recording".

### Fixed

- **`<Text variant="code">` is monospace now** in both kits: they ship JetBrains Mono (SIL OFL,
  fetched by the build, embedded), since Slint doesn't resolve the generic `monospace` family.
- **A wrapping `<Text>` under `@if` in a `<View>`** got the height of one line, so its View came out
  too short (a chat bubble's last lines spilled out). Slint's flexbox measures what is under an `if`
  without its width; such a Text is now always there, hidden and emptied, and an empty `<Text>`
  takes no room in both kits.
- **Windows: audio started before the first window** (e.g. in `App::start()`) no longer crashes the
  app: miniaudio now initialises COM apartment-threaded, as the window system needs on that thread.
- **`ragekit eject`** lists every file the build fetches for a kit (now also its font) for
  `.gitignore`.
- An app that ends without running its event loop (a second launch handing over to the running
  one) no longer crashes on exit: the host released PHP closures after PHP had shut down.

### Changed

- **Backends:** `RageKit\Backend` gains `startTimer()`/`stopTimer()` (ticks come back as
  `Events::deliver('@timer', $id, 'tick', '')`), `setVisible()`, `raise()`, `links()`,
  `claimInstance()`, `registerLink()`, `openUrl()`, `utcOffset()` and `cacheDir()`. The Slint bridge exports
  `rk_timer_*`, `rk_links_*`, `rk_open_url`, `rk_utc_offset`, `rk_window_set_visible` and
  `rk_window_raise`; the dev protocol has `timer-start`/`timer-stop`, `hide`/`show` (and a
  headless-only `advance <ms>` control, since Slint's testing backend mocks time).
- **The core element contract:** `Entry` gains the event `onSubmit`; `Textarea` gains `maxRows` and
  `onSubmit: { callback: submitted, enables: submit-on-return }` (a new `kit.yml` event option:
  using the event sets that bool property). A kit of your own should add them (see the shadcn and
  Material kits); templates that use them otherwise fail to build with that kit. New core element
  `ContextMenu` (see docs/kits.md); a kit without it falls back to Material's. A kit's `Text`
  should take no room when its text is empty (the compiler hides a `<Text>` under `@if` in a
  `<View>` that way).

## [0.6.0] - 2026-10-25

Lists of objects in templates (`RageKit\Collection`) with an image per row, TypePHP 0.9.5, and
Windows fixes. Nothing changes for 0.5 apps, except: run `ragekit setup` again (new TypePHP), and
remove a `maxWidth` you added to wrapping Views as a workaround (it still works, it's just not
needed). Bridges and kits: `rk::Instance` gained `set_rows()` (a no-op by default) and the bridge
exports `rk_rows_*`.

### Added

- **Lists of objects in templates.** A `RageKit\Collection` subclass names its item class in
  `const OF`; `@foreach ($devices as $device)` then reads the items' typed members:
  `{{ $device->name }}`, `{{ $device->label() }}`, in text, attributes, `@if` and handler
  arguments, checked at build time. Collections work as screen, window and store members;
  `count($devices)` counts them. Change them with `add()`, `[] =`, `set()`, `remove()`, `clear()`.
  Only rows that changed are redrawn. `ragekit dev` keeps collections across PHP restarts.
- **Images inside `@foreach`.** `<Image source="{{ $device->image }}">` and
  `@foreach ($photos as $photo) <Image source="{{ $photo }}" />` show each row's own image,
  resolved like single bound images (registered assets, files, web images downloaded once and
  cached), with `fallback` per row.

### Fixed

- **A wrapping `<View>` (`flexWrap: 'wrap'`) no longer caps the window at one child's width.**
  Slint's wrapping flexbox reported a maximum width of about one item, so a list of 440 px cards
  kept a 940 px window at 472 px. A wrapping View without a `width`/`maxWidth` of its own now grows
  with the window; the `maxWidth: 10000` workaround can go.
- **Nano builds on Windows (MSVC) link again** with TypePHP 0.9.5: `ragekit setup` applies a php-nano
  patch on Windows (SHA-3 config, CRC32 and ReflectionFiber code Nano doesn't build). Run
  `ragekit setup` again.
- **Windows normal builds copy PHP's DLLs next to the executable** (`php8ts.dll`, `phpx.dll`,
  `libmpdec`, `gmp`, `mpfr`) from the installed TypePHP release, on every build. The app now starts
  without PHP on PATH, and a copy left from an older TypePHP no longer wins over the new one (that
  showed as a missing entry point such as `?empty_string@php@@…` after updating).

### Changed

- **TypePHP 0.9.5.** `ragekit setup` now installs TypePHP v0.9.5 (was v0.9.4 plus 8 commits); run
  `ragekit setup` again after updating. Among its fixes: writes through a property to an
  `ArrayAccess` object (`$this->items[] = $x`) now call `offsetSet()` instead of replacing the
  object with an array, and tpc creates the output folder itself.

## [0.5.0] - 2026-10-24

Images from PHP: registered assets, files and web images behind the same `source`. Nothing changes
for 0.4 apps; kits with an `image` prop and custom bridges see the additions under Changed.

### Added

- **Images from PHP** (docs/templates.md, "Image"): `source="{{ $cover }}"` shows whatever a string
  property, method or `$store` value holds while the app runs: a registered image, a file, or an
  `http(s)://` URL, downloaded in the background (http module) and cached in the user's cache
  folder. `fallback="…"` is shown while a bound image is empty, loading or failed.
- **Registered images:** `App::assets()` returns classes of path constants (`['images' =>
  Images::class]`); templates show them as `$assets->images->logo`, the build checks and embeds
  them, and `Images::LOGO` in PHP switches a bound image to the embedded copy.
  `ragekit make:assets Images` creates such a class.
- demo/fetch shows the repository owner's avatar.

### Changed

- **Kits:** `image` props can be bound (`in property <image>` set from PHP), and
  `source="{name}"` (the old spelling) now says to write `{{ $name }}`.
- **Bridge C API:** `rk_set_image_asset`, `rk_set_image_file`, `rk_cache_dir`; generated window
  instances implement `set_image()` (and `asset()` when the app registers images).

## [0.4.0] - 2026-10-24

Generators for screens, windows, components, stores, services and flows, templates that find
themselves, and two crash fixes. Nothing changes for 0.3 apps; a custom backend implements one new
method (`printError()`, see Changed).

### Added

- **Generators:** `ragekit make:screen`, `make:window`, `make:component`, `make:store`,
  `make:service` and `make:flow` create a class (and, for screens, windows and components, its
  `.rk` template) in the recommended folders (`src/Screens`, `src/Windows`, `src/Stores`, …).
  `make:store` also adds the store to the app's root store. `ragekit stub:publish` copies the
  stubs into the app's `stubs/` so it can change what `make:` writes. Docs: docs/make.md.
- **Templates find themselves:** a screen, window or component without `template()` uses
  `templates/<its path under src/>.rk`, e.g. `templates/Screens/LoginScreen.rk` for
  `src/Screens/LoginScreen.php`. Overriding `template()` still works.
- **`App::uncaughtException()`:** where exceptions nobody caught in a handler or a module event
  end up. By default they're printed to stderr; override it to show or log them.

### Fixed

- An exception a click handler or a module event's callback didn't catch ended the app ("Fatal
  error" in normal builds, a segfault in Nano builds). It's now printed and the app keeps running.
- An app could crash on exit while a sound was playing: the audio module freed its sounds while
  miniaudio's audio thread was still mixing them. It now shuts the engine down first.

### Changed

- **Backends:** `RageKit\Backend` gains `printError(string $line)` (the Slint backend writes to
  stderr through the bridge's new `rk_print_error`, since Nano PHP has no `STDERR`).

## [0.3.0] - 2026-10-24

The app gets a shape: an app class you extend, a `Window` object per OS window, and app-wide state
in stores. This release breaks 0.2 apps; "Upgrading from 0.2" below lists every change.

### Added

- **The app class.** Apps extend `RageKit\App`: `firstScreen()` names the main window's first
  screen, `title()`, `width()` and `height()` its title and size, `createStore()` the app's state
  and `start()` runs once the main window is open. `main()` becomes `(new MyApp())->run()`.
  `$this->main()` is the main window.
- **Stores** (docs/state.md): `RageKit\RootStore` holds the app's stores (`RageKit\Store`), each a
  typed public property. PHP reads them typed as `AppStore::get()->session`; templates of screens
  and windows read `{{ $store->session->userName }}` and `{{ $store->session->signedIn() }}`, call
  `onClick="$store->session->signOut()"` (with arguments too) and bind inputs two-way to
  `{{ $store->settings->darkMode }}`. Every window showing a store value follows it. Stores tell
  the app what happened with events (`$this->emit('signedOut')`, `->on('signedOut', …)`), so the
  app class turns them into navigation and stores never navigate. All of it is checked at build
  time and compiles in Nano builds. `ragekit dev` keeps the stores across PHP restarts.
- `demo/navigator` signs in: a sign-in screen, the user's name and Sign out in the title bar, and
  the app class resetting the window on `signedIn` / `signedOut`.

### Changed

- **`Window` replaces `Layout`.** Every OS window is a `RageKit\Window`: the plain `Window` keeps
  the OS's title bar, a subclass with a template draws its own (what a layout did). It owns the
  window's navigator (`$window->navigator()`), its toasts, `close()`, `minimize()`,
  `toggleMaximize()`, `$maximized`, and `back()` / `canGoBack()` for a back button.
- **Closing the main window ends the app** and closes the other windows; closing another window
  only closes it. (Before, the app ended when the last window closed.) Apps that should keep
  running override `App::mainWindowClosed()`.
- `App::open()` returns the new `Window` instead of an id.
- The navigator is only the stack (`push`, `back`, `replace`, `reset`, `canGoBack`, `top`, `depth`,
  `stack`); toasts moved to the window.
- `ragekit dev` loads every file that declares a function (main.php) up front, also when it
  declares the app's class too.

### Upgrading from 0.2

- **The app class.** Move what `main()` did into a class: `final class MyApp extends App` with
  `firstScreen()` returning the screen you opened, and `title()`, `width()`, `height()` returning
  what you passed to `open()`. `main()` becomes `(new MyApp())->run();`. `new App()` no longer works
  (`App` is abstract).
- **Layout → Window.** `extends Layout` → `extends Window`, `use RageKit\Layout` →
  `use RageKit\Window`, and in screens `public static function layout(): string` →
  `public static function window(): string`. A screen that returned `''` from `layout()` drops the
  method (the default is `Window::class`). Templates stay as they are.
- In a screen, `$this->layout` is gone: use `$this->currentWindow()`.
- `App::open()` returns a `Window`; `App::close($id)` is gone: `$window->close()`.
- A window that should outlive the main window can't anymore unless the app overrides
  `mainWindowClosed()`; e.g. counter-slint's About closes with the main window now.
- `$store` is reserved in templates: rename a screen property or a loop variable called `store`.
- Kits, modules, `.rk` syntax and `project.yml` are unchanged.

## [0.2.0] - 2026-10-22

### Added

- The `http` module: HTTP and HTTPS requests on a worker thread, so the window never waits
  (`RageKit\Http\Http::get($url)->send(fn (Response $r) => …)`), with headers, bodies, timeouts,
  downloads to a file with progress, and cancelling. Works in Nano builds. Linux uses libcurl
  (building needs `libcurl4-openssl-dev`), Windows WinHTTP. Example: `demo/fetch`.
- **Rageblade** templates: a Blade-flavoured syntax in `.rk` files, compiled ahead of time like
  the rest: `{{ expressions }}` (a strict, typed PHP subset: properties, methods, constants,
  arithmetic, comparisons, logic, ternaries, `count()`), `@foreach ($list as $i => $item)`,
  `@if`/`@elseif`/`@else`, and handlers with expression arguments (`onClick="move($i, 1)"`).
  The older syntax (`{name}`, `each=`, `when=`) still builds; `each=`/`when=` print a hint.
- **Styles, React Native's way:** a `STYLES` constant with React Native's property names,
  `style="card row"`, conditional styles with `@style(['selected' => $cond])`, inline style
  attributes that take expressions (`width="{{ $p * 200 }}"`), and `transition` to animate style
  changes. Kit elements take the outer-box styles (size, margin, flex, position, opacity; Label
  also text styles).
- **`<View>`:** React Native's box: background, border, corners, clip and shadow around a flexbox
  layout (direction, wrap, justify/align, gap, padding), with `position: 'absolute'` children for
  corners and overlays. A root `<View>` fills the window. The demos use Rageblade now, and
  kitchen-sink's Layout tab shows View, wrapping, a corner badge and a styled selectable list.
- `ragekit eject <kit> [name]` copies a kit (shadcn, material, or a Composer kit) into the app's
  `kits/` folder with its components renamed, and switches `project.yml` to it, so the app can
  change how elements are drawn. `ragekit eject` lists the kits.
- `<Dialog open="{{ $confirmDelete }}" title="…">`: a dialog over the whole window, shown while a
  bool property is true; a click outside it or Esc closes it.
- `$this->toast('Saved')` in a screen or layout shows a message in the window's bottom-right
  corner for about 3 seconds.
- `<DropdownMenu text="⋯">` with `<MenuItem text="…" onClick="…" />`s: a button that opens a menu;
  each item calls its own handler.
- `<Text variant="h1">Settings</Text>`: React Native's Text with shadcn's typography variants (`h1`
  to `h4`, `p`, `lead`, `large`, `small`, `muted`, `code`, `blockquote`); the text is the element's
  content, `{{ expressions }}` included. `Label` is unchanged.
- **Navigator:** a window holds a stack of screens. `$this->navigator()->push(new PhotosScreen($album))`
  shows the next screen in the same window, `back()`, `replace()` and `reset()` move around, and a
  covered screen keeps its state. Layouts get `back()` / `canGoBack()` for a back button; Alt+Left
  goes back too. `shown()` / `hidden()` hooks on Screen. Screens sharing a layout compile into one
  Slint window component (a page each); `ragekit dev` keeps the whole stack across PHP restarts.
  Toasts now belong to the window, so they stay up across navigation. Example: `demo/navigator`,
  docs: docs/navigation.md.
- Navigation core elements `Sidebar`, `NavList` (two-way `selected`), `Breadcrumb` (`onSelect`
  calls the handler with the clicked item), `Pagination` (two-way `page`) and `<Accordion>` with
  `<Section>`s (one open at a time), in shadcn and Material; kitchen-sink's new Navigation tab
  shows them. Kit events can now pass a value: `onSelect: { callback: selected, value: string }`.
- Core elements `Switch`, `Textarea`, `RadioGroup`, `Toggle`, `Badge`, `Avatar`, `Alert`,
  `Skeleton` and `Spinner`, in the shadcn and Material kits. `demo/kitchen-sink` shows them in two
  new tabs and has its own title bar.
- Layouts: `RageKit\Layout` frames screens that name it in `layout()`, with its own template
  (`<Content />` marks the screen), state and handlers, and a context interface the screens
  implement (`{context.title}`). Such windows are frameless: `<WindowDrag>` moves the window
  (double-click maximises), `<WindowControls />` adds the kit's minimise, maximise and close
  buttons, and the edges resize. On Linux the app moves and resizes the window itself (no window
  manager snapping) and these apps run on XWayland in a Wayland session (`RAGEKIT_WAYLAND=1` keeps
  Wayland). On Windows the OS moves and resizes the window (with snapping). Example:
  `demo/titlebar`.

### Upgrading from 0.1

- Templates written for 0.1 still build: `{name}`, `each=` and `when=` work and print a hint
  pointing to `{{ }}`, `@foreach` and `@if`.
- New methods on the base classes: `Screen` has `shown()`, `hidden()` and `navigator()`, `Layout`
  has `back()` and `canGoBack()`. A screen or layout of yours with a method of one of those names
  (and another signature) must rename it.
- Kits written for 0.1 keep working: core elements they don't provide (Text, Dialog, DropdownMenu,
  the navigation elements, toasts) fall back to Material's. A kit that wants to offer them follows
  the contract in docs/kits.md.

## [0.1.0] - 2026-10-18

The first release. Experimental: Linux is where it's built and tested, Windows works but
is tested less, macOS isn't supported yet.

### Apps

- Screens and components as PHP classes (public properties are state, public methods are
  handlers), each with a `.rk` template; `App::open()` for multiple windows.
- Templates: `VStack`/`HStack`, bindings (`{count}`, computed methods), two-way inputs, `when` and
  `each`, child components with props, `<Tabs>`.
- Core elements every kit accepts: Label, Button, Entry, Checkbox, Slider, Select, Image,
  Progress, Card, Separator.
- Kits: `material` (Slint's Material 3 library) and `shadcn`; kits in the app (`kits/`) and in
  Composer packages; `image` props embedded at build time.
- Native modules (runtime-loaded C++ libraries with a generated PHP API), starting with `audio`
  (WAV, FLAC, MP3 via miniaudio); events from native threads; `assets:` copied next to the
  executable.

### Building

- `ragekit build` / `run`: templates compiled ahead of time to Slint and C++, PHP compiled by
  TypePHP; normal builds or Nano builds (`nano: true` or `--nano`, a stripped-down PHP runtime
  compiled into the executable); renderer choice (`software`, `femtovg`, `skia`).
- `ragekit dev`: hot reload of templates, kits, images and PHP with screen state kept (Linux).
- `ragekit setup` installs the pinned TypePHP and Slint (shared per user, one folder per set of
  pins; `--prune` deletes the ones of other versions); `ragekit doctor` checks everything a build
  needs.
- Starter app: `composer create-project ragekit/starter`.

### Known limits

- TypePHP compiles a subset of PHP; code that runs in `ragekit dev` can still fail to build.
- Windows: normal builds don't copy PHP's DLLs next to the executable; `ragekit dev` is Linux-only,
  and native modules are less tested there.
- Normal builds on Linux compile a private PHP once (~10 minutes) unless PHP's embed library is
  installed (`libphp8.4-embed`, plus `php8.4-dev`, `cmake`, `libgmp-dev` and `libmpfr-dev`).
- No networking in Nano builds; PHP runs on the UI thread.
